# session-card — shareable project snapshot

Read-only skill. Composes a single markdown card summarizing the current scribe-enabled project's state. The card is the unit of social-share — copy-paste it into a tweet, Reddit post, Discord message, or take a screenshot.

## Hard rules — never violate

- **Read-only.** No edits to STATE.md, DECISIONS.md, status memos, memory files, or anything else. Pure observation + formatting.
- **Bail silent if `docs/STATE.md` is missing.** Project not scribe-enabled — emit one line "session-card: project not scribe-enabled (no docs/STATE.md found). Run init-project-scribe first." and stop.
- **No external network calls.** Everything from local files + git.
- **No PII leakage.** Skill reads commit author names + emails from git log and MUST exclude them from the card. Card shows commit count + commit messages only, never author identity.
- **No new files.** Card is emitted to chat. User decides whether to save / paste / screenshot.

## When to invoke

- User says: "session card", "share my session", "/session-card", "/project-scribe:session-card", "show me a card", "summarize my session", "what does my project look like right now"
- After a long session as a wrap-up summary (pairs naturally with `/project-scribe:handoff`)
- When user wants a screenshottable artifact for social media

## Pre-flight

1. Confirm `docs/STATE.md` exists in cwd. If missing → bail per Hard rules.
2. Identify the scribe-enabled project root (cwd).
3. Resolve memory dir slug: `~/.claude/projects/<slug>/memory/` (slug rule from `hooks/stop-mark-memory`: convert `/c/Users/...` → `C--Users-...` etc.)
4. Read plugin version from `.claude-plugin/plugin.json` if present (for footer credit).

## Data sources

Pull these in order. If any source missing, render the card with a "—" placeholder for that field rather than omitting the row.

### A. STATE.md fields

Parse these blocks:

- `## Current focus` → first 1-2 sentences, max 200 chars
- `## Last shipped` → first 3 bullet items
- `## Next up` → first 3 bullet items
- `## Deferred` → count items only (don't list)

### B. DECISIONS.md count + most-recent

- Count `## YYYY-MM-DD —` headings
- Capture last entry's date + title text only

### C. Recent git activity (last 7 days)

```bash
git log --since="7 days ago" --pretty=format:"%h %s" --no-merges
```

Extract:
- Total commit count
- Top 3 commit messages (subject only)

If `git log` fails (not a git repo, or no commits in 7 days) → "no git activity in last 7 days"

### D. Memory health (if memory dir exists)

For `<MEM_DIR>` and `<MEM_DIR>/daily/`:

- Count `*.md` files (excluding `MEMORY.md`)
- For files with frontmatter, compute `weeks_idle` and bucket:
  - `hits >= 10` → load-bearing
  - `weeks_idle <= 4` → active
  - `weeks_idle > 4` and not load-bearing → idle

If `.bump-log` exists, get mtime → "last hook fire: Xh ago" or "Xd ago"

If memory dir absent → "memory: not yet initialized"

### E. Status memos

- Count `*.md` files in `docs/status/` (excluding README.md and TEMPLATE.md)

## Card output format

Single markdown block, fenced inside triple-backticks so the user can copy verbatim. Total target: ≤ 60 lines, fits in a Reddit post / Discord message without truncation. Keep emojis tasteful — 1 per row, not a wall.

```
🪶 **<project-name> — session card**

📌 **Current focus**
> <one-or-two-sentence focus from STATE.md>

✅ **Decisions logged**
<N> total · most recent: "<latest decision title>" (<date>)

📦 **Last shipped**
- <bullet 1>
- <bullet 2>
- <bullet 3>

🚀 **In flight**
- <next-up bullet 1>
- <next-up bullet 2>
- <next-up bullet 3>

⏸️ **Deferred**: <N> items

🧠 **Memory**
<N> files · <K> load-bearing · <M> active · <I> idle
Last hook fire: <Xh / Xd ago>

📊 **This week**
<N> commits · <M> decisions · <K> status memos
Top: <commit msg 1>, <commit msg 2>, <commit msg 3>

— Generated by [project-scribe](https://github.com/forty4420/project-scribe) v<X>
```

### Field rules

- **Project name**: read from STATE.md's `# <Title>` first heading, or fall back to cwd basename. Strip a leading `Project State — ` if present.
- **Dates**: ISO format (YYYY-MM-DD).
- **Char limits**: each STATE.md bullet trimmed to 80 chars max + ellipsis. Truncate on the last whitespace boundary at or before char 77 (so ellipsis lands cleanly between words, never mid-word). If the bullet has no whitespace before char 77, truncate at char 77 anyway — last resort.
- **"Last hook fire"**: if `.bump-log` mtime is within 24h, format as `Xh`; else `Xd`. If file missing, "not yet fired".
- **No fluff**: omit empty sections by replacing with "—" rather than dropping rows. Keeps shape consistent screenshot-to-screenshot.
- **Footer**: always present. Drives the powered-by-scribe distribution loop.

### Bullet truncation algorithm

For a bullet `text` that exceeds 80 chars:

1. Take `text[0:77]` as the candidate.
2. Find the last space character in the candidate. If found at position `p`, truncate to `text[0:p]` + `…` (ellipsis).
3. If no space found in `text[0:77]`, truncate to `text[0:77]` + `…` (rare — only happens for a single >80-char unbroken token).
4. Strip backticks and other markdown that might unbalance after truncation. Specifically: if the truncated string contains an odd count of backticks, append a closing backtick before the ellipsis to keep markdown valid.

This makes truncated bullets read clean (no "fie…" or "into d…") and keeps fenced code spans/inline code from breaking the card's markdown rendering.

## Optional PNG render

If user asks for "as image", "as PNG", "screenshot version", or invokes with `--png` flag:

1. Note that PNG generation requires either:
   - The `nano-banana-pro` plugin installed + `GEMINI_API_KEY` set, OR
   - Manual screenshot of the rendered markdown
2. If `nano-banana-pro` available, suggest a prompt the user can pass to it:
   ```
   Generate a 1200x630 social-card PNG with dark navy background (#0f172a),
   monospace font, green accents (#10b981), rendering this markdown content
   as a clean infographic with the project-scribe logo footer:
   <paste card markdown>
   ```
3. Default = markdown only. Don't auto-render PNG without explicit user opt-in.

## Don't

- Don't include git author names or emails. Privacy + the footer credits the project, not the user.
- Don't fetch from network. Card is fully local.
- Don't write the card to disk. User chooses where it goes.
- Don't include decay-system internals (.bump-log line counts, individual memory file scores, etc.). That's `/scribe-status`'s job. This card is the social-share surface.
- Don't run on projects without `docs/STATE.md`. Bail per Hard rules.
- Don't include base-scope guardrails details. Card is for the universal audience; guardrails users have their own dashboards.
- Don't speculate about counts you can't verify. If a source is missing, "—" placeholder.

## Distribution intent

This skill IS the marketing loop. Every card someone screenshots and posts is one distribution event. Every powered-by footer is one passive backlink. The card is short enough to fit a tweet image, dense enough to be interesting, and self-explaining enough that a viewer doesn't need to read the README to grok what scribe does.

If the user shares a card, the card sells the tool. That's the whole point.
