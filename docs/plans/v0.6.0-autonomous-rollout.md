# Scribe v0.6.0 — Autonomous Rollout Plan

**Goal:** Ship feature-widened, well-tested v0.6.0 release that strengthens Scribe's competitive moat. User initiates session and walks away. Smoke-test held to end (user runs in real session). Agent works autonomously through phases, commits at phase boundaries, halts on red flags.

**Operating mode:** AFK-friendly. Most steps = AFK (autonomous). HITL flagged explicitly. Agent never claims completion without verification.

**Halt conditions (any one = stop, await user):**
- Test failure that isn't an obvious typo fix
- Ambiguous design call not covered in plan
- Touching files outside plan scope
- Three consecutive failed attempts at same task

## Phase 1 — `/scribe-status` smoke-test command (1-2 hr, AFK)

**Goal:** Read-only diagnostic skill. Reports decay-system health without modifying anything.

**Subagent:** `general-purpose`. Scope: build skill + slash command. Return diff.

**Files to create:**
- `skills/scribe-status/SKILL.md`
- `commands/scribe-status.md` (slash command alias)

**Skill behavior:**
1. Resolve memory dir via existing slug rule.
2. If missing → report "no scribe memory yet, hook hasn't fired or project not yet active."
3. If present → read every `*.md` in dir + `.bump-log`. Report:
   - Total memory files
   - Files with frontmatter vs without (backfill progress)
   - Per-file: `last_used`, `hits`, computed decay score, status (active/idle/decay-candidate/load-bearing)
   - `.bump-log` line count + age (last entry timestamp)
   - Date of last `.bump-log` prune (mtime)
4. Report Stop-hook health:
   - Was hook registered in `hooks/hooks.json`? (read it, check Stop entry exists)
   - Last `.bump-log` entry within 24h = hook firing
   - No `.bump-log` entries but memory files exist = hook misconfigured or never fired

**Output format:** Single markdown table + summary block. Plain text, no JSON.

**Hard rules:**
- Read-only. Never modify any memory file, bump-log, or hook config.
- Bail silent if `docs/STATE.md` missing (not scribe-enabled project).
- Compute decay score using same formula as `compact-memory` Pass 0:
  ```
  weeks_idle = floor((today - last_used) / 7)
  decayed_hits = hits * (0.9 ^ weeks_idle)
  score = (decayed_hits + 1) / (weeks_idle + 1)
  ```

**Verification:**
- Skill file passes YAML frontmatter parse
- Skill described in plain language; agent can find via Skill tool
- Sandbox: build fake memory dir with 3 files, run skill mentally (or as test bash script), confirm output shape

**Halt-risk:** low. Read-only, no hooks, no state mutation.

**Phase commit:** `feat(skills): add scribe-status read-only diagnostic`

## Phase 3 — Cross-reference lint skill (2-3 hr, AFK)

**Goal:** New skill `xref-lint` scans project artifacts for inconsistencies.

**Subagent:** `general-purpose`. Scope: design skill, build per-check logic in skill body (declarative, no scripts). Return skill file + sample run on actual scribe repo.

**File to create:**
- `skills/xref-lint/SKILL.md`

**Checks (start narrow, expand later):**
1. **Orphan plans:** plan in `docs/plans/` with no spec ref in `docs/specs/`
2. **Stale memo links:** status memo in `docs/status/` references file path that no longer exists
3. **Contradiction probe (low-confidence):** scan DECISIONS.md for entries where both contain "always X" and "never X" for same X. Flag as candidate, never auto-resolve.
4. **Missing status memo:** spec marked shipped in STATE.md but no status memo exists

**Skill output:** markdown table — check name, severity (info/warn/error), location, suggested action.

**Hard rules:**
- Read-only. No auto-fix. User decides on each finding.
- Skip if STATE.md missing.
- Confidence-tag every finding: `high`/`medium`/`low`. Contradiction probe = `low` (false positives expected).

**Trigger:**
- User invokes "lint xref" / "check cross-references" / `/xref-lint`
- Optionally invoked by `auto-handoff` as quality gate (deferred — wire later, not Phase 3)

**Verification:**
- Run skill mentally against current scribe repo
- Expect: 0 orphan plans (plans dir tracks them), 0 stale links (recent housekeeping), maybe 1-2 missing status memos
- Compare against actual file inventory before declaring success

**Halt-risk:** medium. Contradiction probe is the risky check — skip if logic gets fuzzy. Better to ship 3 solid checks than 4 with false positives.

**Phase commit:** `feat(skills): add xref-lint for orphan plans, stale links, contradictions`

## Phase 4 — PreCompact snapshot hook (2-3 hr, AFK)

**Goal:** Bulletproof handoff. Auto-snapshot before context compact event, restore on next SessionStart.

**Subagent:** `general-purpose`. Scope: hook script + SessionStart restore wiring. Return both files + sandbox test output.

**Files to create/modify:**
- `hooks/pre-compact` (new bash script)
- `hooks/session-start` (modify: detect snapshot file, inject content if present, then delete snapshot)
- `hooks/hooks.json` (register PreCompact hook)
- `skills/auto-handoff/SKILL.md` (note: PreCompact now writes snapshot automatically; explicit /handoff still works as override)

**Snapshot file location:** `docs/.scribe-snapshot.md` (gitignored)

**Snapshot contents (priority-tiered, ≤2KB target):**
- P1: last user prompt (verbatim)
- P1: current focus from STATE.md
- P1: last 3 DECISIONS entries (titles only)
- P2: in-flight files (extract from recent transcript turns if accessible — best effort)
- P3: open todos / next-up items from STATE.md

If 2KB budget tight, drop P3 first, then P2.

**`pre-compact` script behavior:**
1. Bail if no `docs/STATE.md`.
2. Read STATE.md current focus + next up + last shipped.
3. Read DECISIONS.md, extract last 3 entry headers.
4. Read transcript stdin → extract last user turn.
5. Compose snapshot markdown.
6. Write to `docs/.scribe-snapshot.md`.
7. Exit 0 always.

**Optional debug logging (added across all hooks in this phase):**
- If env var `SCRIBE_DEBUG=1` set, append diagnostic line to `~/.scribe-debug.log`:
  ```
  YYYY-MM-DD HH:MM:SS <hook-name> <action> <file-or-result>
  ```
- Default off → existing silent-no-op behavior preserved.
- Add to `pre-compact`, `stop-mark-memory`, `session-start`, `userprompt-context-warn`.
- Document env var in README troubleshooting section.

**`session-start` modification:**
- After existing scribe-enabled check, also check for `docs/.scribe-snapshot.md`.
- If present: include contents as `additional_context` in JSON output, then delete snapshot file (one-shot consumption).
- If absent: existing behavior unchanged.

**Edge cases:**
- Snapshot exists but stale (mtime > 7d): still inject, but flag as "stale snapshot from <date>"
- Snapshot exists from non-compact session start: harmless, gets consumed and deleted

**Gitignore:**
- Add `docs/.scribe-snapshot.md` to `.gitignore`

**Verification:**
- Sandbox: fake STATE.md + DECISIONS.md + fake transcript JSON, run `pre-compact`, confirm snapshot written
- Run `session-start` after, confirm snapshot consumed + deleted
- Edge: run `session-start` when no snapshot present, confirm existing behavior

**Halt-risk:** medium. Modifies live `session-start` hook. Test in sandbox before declaring done. If `session-start` test fails, revert that file change before phase commit.

**Phase commit:** `feat(hooks): add pre-compact snapshot + session-start restore`

## Phase 7.5 — CI/CD: shellcheck + JSON lint (30 min, AFK)

**Goal:** Catch bash syntax errors + malformed JSON before commit. Free quality signal for repo visitors (green CI badge).

**Files to create:**
- `.github/workflows/lint.yml`

**Workflow:**
- Trigger: push + pull_request on master
- Jobs:
  1. **shellcheck** — run on `hooks/session-start`, `hooks/stop-mark-memory`, `hooks/pre-compact`, `hooks/userprompt-context-warn`. Use `ludeeus/action-shellcheck@master` action.
  2. **json-lint** — `jq empty < hooks/hooks.json && jq empty < .claude-plugin/plugin.json`
  3. **markdown frontmatter check** — verify every `skills/*/SKILL.md` has valid YAML frontmatter (opens + closes with `---`).

**Add CI badge to README:**
```
[![CI](https://github.com/forty4420/project-scribe/actions/workflows/lint.yml/badge.svg)](https://github.com/forty4420/project-scribe/actions/workflows/lint.yml)
```

**Hard rules:**
- Workflow runs on Ubuntu only (sufficient for shellcheck/jq).
- Polyglot `run-hook.cmd` is excluded from shellcheck (contains intentional CMD batch block — would error on shellcheck).
- No auto-format. Lint only. Failures = warning, not block, until v0.7.0.
- **All lint jobs must use `continue-on-error: true`** so first-run shellcheck noise can't block merge. Tighten in v0.7.0 once known findings cleaned up.

**Verification:**
- Workflow YAML parses (`yamllint` or visual check)
- Push branch, confirm Actions tab shows run
- All checks green (or known-failing items documented)

**Halt-risk:** low. Adds files, doesn't modify existing hooks. Worst case: lint catches real bug we then fix.

## Phase 10 — Smoke test (HITL — user runs)

**Why HITL:** Real session needed to verify hooks fire. Sandbox tests cover unit behavior; only live use catches integration bugs.

1. `/scribe-status` — confirm output shape, verify v0.5.0 decay state

## Subagent dispatch strategy

**Inline (main session):** Phases 0, 2, 6, 7, 8, 9, 10. Small scope, fast feedback, low risk.

**Subagent (`general-purpose`):** Phases 1, 3, 4, 5. Each phase = one subagent invocation with self-contained brief. Subagent returns:
- Diff of changes
- Test output if any
- Halt-flag if hit halt condition

**Why subagent:** keeps main-session context lean. Each subagent gets fresh context budget. Main session orchestrates + verifies.

**Subagent prompt template (per phase):**
```
You are implementing Phase <N> of v0.6.0 rollout. Read docs/plans/v0.6.0-autonomous-rollout.md for full plan and halt conditions. Implement only Phase <N>. Return:
1. List of files created/modified
2. Diff summary
3. Sandbox test output (if applicable)
4. Halt-flag (none/yes-because-X)

Do not commit. Main session commits after verification.
```

## Halt protocol

**On halt:**
1. Agent stops. Does NOT attempt fix.
2. Writes halt note to `docs/plans/v0.6.0-halt-<phase>.md` using template below.
3. Reverts working tree to last good phase commit (`git reset --hard HEAD`)
4. Awaits user.

**No silent fallbacks.** Better to halt than ship broken work to a user who's at work and can't review.

### Halt-note template (paste, fill, save)

```markdown
# v0.6.0 halt — Phase <N>: <phase title>

**Time:** <YYYY-MM-DD HH:MM local>
**Branch:** v0.6.0-feature-stack
**Last good commit:** <SHA from `git log --oneline -1` after reset>

## Where it stopped

Phase <N>, step <step number or description>.

## Symptom

```
<paste exact error message, command output, or ambiguity question>
```

## What was tried

1. <attempt 1 and result>
2. <attempt 2 and result>
3. <attempt 3 and result>

## What user input is needed

- [ ] <specific question 1, with binary or multiple-choice if possible>
- [ ] <specific question 2>

## State of working tree

- `git status` output: <paste>
- Phases completed cleanly: <list>
- Phases remaining: <list>

## How to resume after user input

<one-paragraph plan: which file to edit, which command to retry, etc>
```

**Hard rule:** halt note MUST be written before working tree reset. If reset fails, agent leaves tree as-is and writes second note explaining reset failure too.
