## What NOT to lose

1. **Caveman mode active** — full intensity. User wants terse, fragment-OK responses. Code/commits/PRs still written normal. "stop caveman" / "normal mode" disables.
2. **No shortcuts policy (user explicit):** when picking architectural options, the user does NOT want minimal-effort default. (b) hybrid resolution + (b) bounded drift detection + (b) honest fuzzy match + (c) markdown report w/ suggested fixes was the locked pattern for v0.7.4.
3. **Honesty contract:** scribe-verify multi-match fuzzy SHA = ⚠️ ambiguous abort, NEVER silent guess. This was a deliberate design choice the user pushed back on. Carry forward to similar drift/diagnostic features.
4. **`scripts/` dir precedent:** v0.7.4 introduced `scripts/`. Future commands needing heavy bash logic should use the same SKILL.md (thin wrapper) + scripts/<name>.sh (heavy lifter) split. Tests under `tests/scripts/<name>.bats`.
5. **Subagent-driven flow with two-stage review at chunk boundaries works.** Per-chunk: implementer → spec compliance review → code quality review → fix loop → next chunk. Plus final cross-chunk review before merge. Pattern is calibrated for this codebase.
6. **Worktree submodule init gotcha:** new worktrees from a submodule-using repo need `git submodule update --init --recursive` before tests run. Otherwise bats binary not found. Document if this trips a future contributor.
7. **CI workflow gotcha (caught + fixed):** workflow uses explicit per-dir `bash tests/run.sh tests/<group>` steps. New test groups must add a step — runner-default extension alone doesn't help. Pattern: when adding a new tests/X/ dir, also add `Run X tests` step to `.github/workflows/test.yml`.
